# UP300 support (experimental)

Worked out from two USBPcap recordings of UP Studio 3 / Wand driving a UP300 (firmware 359),
kindly made by Alex Wyatt, and tested by him on his Afinia H+1 (a rebranded UP300, same firmware).

## What the recordings show

| | UP Box+ | UP300 |
|---|---|---|
| USB ID | 4745:xxxx, full speed | 4745:**2790**, high speed |
| Bulk endpoints | OUT 0x01, IN 0x81 | OUT **0x02**, IN 0x81 |
| Info block model id | 0x2710 | **0x2783** ("H+1") |
| Steps/mm X / Y / Z (info block) | 644 / 644 / 3220 | **161 / 161 / 805** |
| Extruder factor (info block) | 40 | 10 |
| Bed frame (info block) | X 6 to 213, Y -262 to -3, Z 210 | X 6 to 213, Y -262 to -3, Z 230 |
| Parameters 0x00-0x5F | (reference) | Same meanings and defaults (e.g. 0x2A 5000, 0x2B 193, 0x36 103, 0x4B 80 000 000) |

- **Same command set.** UP Studio 3 still uses the classic commands on the UP300 for status
  (`76`), parameters (`56`), positions (`70`), the init routine (`4C 30`), the program buffer
  (`43`, `2F`, `58`) and jogging. The motion controller is the same family as the UP Box+.
- **Head position cross-check.** After a 142.6 / -132.5 mm move, the printer reported
  22957 / -21331 steps: 161 steps/mm.
- **Info block in one piece.** The UP300 answers `52 77 A6 5B` with one 1509-byte transfer
  (header 28, name padded to 64, data 56, 8 parameter sets).
- **Print jobs.** UP Studio 3 uploads a whole job file with newer `45 3C` / `45 3E` / `45 3F` /
  `45 40` / `45 21` commands (2040-byte chunks), not as UMC blocks. That format isn't implemented.

## What OpenBoxBridge does

- **USB:** the endpoints are read from the device descriptor. Answers are buffered, so one big
  transfer and several small ones look the same.
- **Printer info:** parsed in either layout. `up3dstatus` reports the model id (status field 19),
  and the app switches to machine type `up300`.
- **Converter and controls:** `settings_up300` sets X/Y 161 steps/mm. The extruder is 213.5, which
  is the UP Box+'s 854 scaled by the info factor (10 against 40). It's set in the app and passed
  as `UP3D_ESTEPS`. Z moves are sent in mm.
- **Sending jobs (test 4):** on the UP300, `up3dload` streams the job into the program buffer
  while it runs (`--method=2`), the same path the home and jog programs use. It waits up to
  45 minutes for room in the buffer, so the bed can heat from cold. The two stored-job methods
  (UP3D's SD slot 5 with counter `C6`, and UP Studio's slot 9 with `63 09 0E` commits) are still
  selectable for testing, but don't work on the UP300 (see test 2).
- **Jog limits:** the app refuses Control-page moves that would leave the UP300's travel.
- **Long control programs** (extrude, withdraw) are streamed on the UP300.
- **Stopping a stream (test 5):** the streaming tool holds the USB connection for the whole
  print, so no other tool can reach the printer. The app passes a file name in
  `UP3D_STOPFILE`; Stop creates that file. Between transfers `UP3D_StreamProgram` checks for it,
  sends no more data, runs the normal stop sequence (`UP3D_StopProgram`: param `0D` = 1, heaters
  off, clear the program buffer) and exits with code 20. The app's own `up3dstatus stop` then
  runs again to confirm. If the tool hasn't ended after 25 s, the app ends it. Closing the app
  while streaming stops the print the same way. The printer's own button does not stop a
  streamed job.
- **Watching a stream (test 6):** every 10 s the streaming tool prints `Status;` + the
  `up3dstatus` fields (`UP3D_PrintStatusLine`, shared with up3dstatus), so the app shows
  temperatures, layer and progress while the tool holds the USB link. It also checks the
  machine state: if the printer is no longer "Running Program" on two checks in a row, it
  prints "Printer details" (internal status `0x0F`, X/Y limit errors `0x1E`/`0x1F`, axis
  steps), runs the stop sequence (heaters off) and exits with code 21. A 45-minute stall or a
  USB failure also turns the heaters off when the printer still answers.
- **Bed preheat (test 6):** `up3dload --method=2 --bed=T --standby=S` heats the bed with the
  same parameter blocks as `up3dstatus bed`, turns a hot nozzle down to S, and waits for the
  measured bed temperature (30 min limit) before streaming. The app passes the first
  M140/M190 temperature from the G-code and 150 C. Stop works during the preheat too.
- **Print area:** the UP300's travel is machine X 6..213 and Y -262..-3. With the bed centre at
  X 125, Y 108 that is about X -122..+137 and Y -102..+105 around the centre, smaller than the
  UP Box+ profile's 255 x 205. A move outside stops the printer with "JogCmd Error". The
  "UP300 USB" printer profile (`tools/make_up300_presets.py`) uses X -120..+120, Y -100..+100,
  and the app warns when a UP300 job was sliced with the UP Box+ profile.

## Test results

- **Test 1 (STOP test, no heat).** The job was stored and started, so storing with method 0 works.
  It homed, then stopped with **"JOG Command Error"** on the printer's screen at the first jog move.
  - That move asked for machine X/Y 0,0, which is outside the UP300's limits (X 6 to 213,
    Y -262 to -3), at 100 mm/s. UP Studio 3 never sends a jog faster than 50 (X/Y) or 10 (Z).
  - Test 2 build fixes this on the UP300:
    - jog speeds are capped at 50 / 10;
    - G28 homes for real instead of jogging to 0,0;
    - an axis that doesn't move is sent as a relative move of 0.

- **Test 2 (Afinia H+1, firmware 6.15).**
  - Info, status, Initialise, Home and jogs work. A 10 mm jog measured 10 mm (±0.5), so
    161 steps/mm is right for X/Y. Bed centre X 130, Y 108; nozzle height 228.6 mm.
  - Control page: after Home the printer reports 0,0, just outside its travel (X 6 to 213,
    Y -262 to -3), so jogs one way give "JOG Command Error". UP Studio's recording shows the same
    home position (0,0) and then a move to X 20, Y -125.
  - Job storing: method 0 never confirmed (`C6` stayed 0 for 60 s). Method 1 "stored", then the
    printer showed **"SD Card Reading Error" / "JOG Command Error"** and stopped after a few seconds,
    with or without the flash drive. Every move in the converted STOP test is inside the travel
    (checked by decoding the job), so the error is the stored-job path itself.
  - Test 4: stream jobs on the UP300; refuse out-of-travel jogs; type-in Z height for calibration.

- **Test 4 (same printer).**
  - X directions as expected; homing and the STOP test squares worked. Bed centre X 125, Y 108;
    nozzle height 228.00 mm.
  - STOP test streamed and ran; Stop in the app stopped it. The printer's own button did nothing
    (a streamed job isn't a job the printer's menu knows about).
  - Extrude 50 mm at 213.5 steps/mm pushed 45-46 mm: about 235 steps/mm (232-237).
  - **First UP300 print:** a 20 mm cube streamed (36 877 blocks; about 3.5 min waiting while the
    bed heated, then data flowed). Purge line and skirt thin (under-extrusion, see above).
  - **Stop during streaming did not work:** the app runs one tool at a time and left the
    streaming `up3dload` running, so each Stop waited behind it. After the USB cable was pulled
    the printer carried on with the blocks it had buffered, and the queued stops then failed
    together. Fixed in test 5 (see "Stopping a stream").

- **Test 5 (same printer).**
  - Stop while streaming worked twice, in under a second. Extrude 50 mm at 235 pushed 51 mm.
  - A 20 mm cube (gyroid infill, 220 086 blocks) ended at the same point twice: after 48 384
    blocks were sent the printer took no more data. It was already Idle ("machine state 3")
    and showed "jog error" (system state "JogCmd Error"): it ended the job itself. The app
    waited 45 minutes and sent no stop, so the heaters stayed on. Fixed in test 6 (see
    "Watching a stream"). The cause is not known yet; a move outside the UP300's travel gives
    the same error, so test 6 adds a UP300 print area and records the details.
  - The bed started at about 47 C of 55 C (fixed wait too short); the nozzle was still hot
    from Extrude and dripped during the bed wait. No temperatures showed while streaming.
  - The diagnostics snapshot was empty: the app ended the diagnostics' up3dsnap as a
    "stuck" tool. Test 6 only ends tools it started (or ones older than the app).
